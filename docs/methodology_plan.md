### 1.2 Forest definition — write this before you touch data

This single paragraph determines every number in your results. Draft it now, get supervisor sign-off, and quote it verbatim in the thesis.

**Recommended definition:**
> Forest is land with tree canopy cover ≥30% over a minimum mapping unit of 0.5 ha (approximately 6 Landsat pixels), with trees capable of reaching 5 m height in situ, **excluding**: tea plantations, rubber plantations, orchards, agroforestry woodlots, and homestead vegetation. Bare ground within a forest boundary arising from temporary disturbance is classified as forest if regrowth is evident within the observation period.

Why each clause matters:

| Clause | Prevents |
|---|---|
| ≥30% canopy | Arbitrary comparison with Hansen (which uses a user-set threshold) |
| 0.5 ha MMU | Salt-and-pepper single-pixel "loss" inflating your area statistics |
| Excluding tea/rubber | **The Sylhet failure mode** — plantations counting as forest and masking real loss |
| Excluding homestead vegetation | Village tree cover in Gazipur registering as forest |

### 1.3 Class scheme

Use four classes, not two. Binary forest/non-forest cannot express the plantation problem.

| Code | Class | Notes |
|---|---|---|
| 0 | Non-forest | Built-up, bare, water, cropland |
| 1 | Natural forest | Sal (Gazipur), hill forest (Sylhet) |
| 2 | Plantation / tea | Trained as a separate class, reported separately |
| 3 | Water | Optional separate class; improves Sylhet haors handling |

Collapse to binary only at the reporting stage, and state that you did.

### 2.1 The audit

For each district, each year 1984–2024, each sensor, count usable scenes in the dry season.

```javascript
var aoi = ee.FeatureCollection('projects/YOUR_PROJECT/assets/gazipur');

function auditYear(year) {
  var start = ee.Date.fromYMD(year - 1, 11, 1);
  var end   = ee.Date.fromYMD(year, 3, 31);
  var l5 = ee.ImageCollection('LANDSAT/LT05/C02/T1_L2')
             .filterBounds(aoi).filterDate(start, end)
             .filter(ee.Filter.lt('CLOUD_COVER', 40));
  var l7 = ee.ImageCollection('LANDSAT/LE07/C02/T1_L2')
             .filterBounds(aoi).filterDate(start, end)
             .filter(ee.Filter.lt('CLOUD_COVER', 40));
  var l8 = ee.ImageCollection('LANDSAT/LC08/C02/T1_L2')
             .filterBounds(aoi).filterDate(start, end)
             .filter(ee.Filter.lt('CLOUD_COVER', 40));
  return ee.Feature(null, {
    year: year,
    l5: l5.size(), l7: l7.size(), l8: l8.size(),
    total: l5.size().add(l7.size()).add(l8.size())
  });
}

var years = ee.List.sequence(1985, 2024);
var audit = ee.FeatureCollection(years.map(function(y) { return auditYear(y); }));
Export.table.toDrive({collection: audit, description: 'gazipur_scene_audit'});
```

**Dry season = 1 November to 31 March.** Bangladesh's monsoon (June–October) makes optical imagery largely unusable, and using mixed-season composites introduces phenological change that your model will read as forest loss.

### 2.2 Decision rule from the audit

| Usable scenes in the window | Decision |
|---|---|
| ≥3 per year | Annual composite is viable |
| 1–2 per year | Use a **3-year moving window** composite centred on the target year |
| 0 | Year is unusable — exclude and say so explicitly |

Expected outcome: 1984–1990 will be thin over Bangladesh (few international ground stations receiving Landsat 5 at the time), and Sylhet worse than Gazipur due to terrain and cloud. Be prepared to move your start year to 1990 or 1995. **A defensible 1995–2024 study beats an undefendable 1984–2022 one.**

### 2.3 Epoch selection

Don't analyse all 40 years at equal depth. Choose **epoch anchors** for the main comparison, plus an annual series for trend:

| Epoch | Purpose |
|---|---|
| T0 (e.g. 1990) | Baseline |
| T1 (2000) | Aligns with Hansen baseline — enables cross-validation |
| T2 (2010) | Mid-point |
| T3 (2024) | Endpoint |

Bitemporal change detection runs on T0→T3 and each consecutive pair. LandTrendr runs on the full annual series.

**Gate 2:** Audit table exported for all three districts. Start year fixed and justified in one written paragraph. Epoch anchors chosen.

**Additional Bandarban condition on Gate 2.** The audit must also confirm

## Phase 3 — Preprocessing

**Duration:** Month 3

### 3.1 Scaling — Landsat Collection 2 Level-2

C2 L2 surface reflectance is stored as scaled integers. **Applying the wrong scale factor is the single most common silent error in student GEE work.**

```javascript
function scaleL2(image) {
  var optical = image.select('SR_B.').multiply(0.0000275).add(-0.2);
  var thermal = image.select('ST_B.*').multiply(0.00341802).add(149.0);
  return image.addBands(optical, null, true)
              .addBands(thermal, null, true);
}
```

After scaling, valid reflectance is 0–1. Clamp to that range; values outside indicate bad pixels.

### 3.2 Cloud and shadow masking

Use the `QA_PIXEL` bitmask, not `CLOUD_COVER` alone (which is scene-level).

```javascript
function maskL2(image) {
  var qa = image.select('QA_PIXEL');
  var dilated = qa.bitwiseAnd(1 << 1).eq(0);
  var cirrus  = qa.bitwiseAnd(1 << 2).eq(0);
  var cloud   = qa.bitwiseAnd(1 << 3).eq(0);
  var shadow  = qa.bitwiseAnd(1 << 4).eq(0);
  var snow    = qa.bitwiseAnd(1 << 5).eq(0);
  var sat = image.select('QA_RADSAT').eq(0);
  return image.updateMask(dilated.and(cirrus).and(cloud)
              .and(shadow).and(snow).and(sat));
}
```

### 3.3 Cross-sensor harmonisation

TM, ETM+, and OLI have different spectral response functions. Comparing an unharmonised 1990 TM composite with a 2024 OLI composite produces a spurious "change" signal. Apply the Roy et al. (2016) OLS coefficients to bring ETM+ into the OLI reference (or vice versa) — cite the paper and put the coefficient table in an appendix.

Band naming must be unified before merging collections:

| Common name | TM/ETM+ | OLI/TIRS |
|---|---|---|
| Blue | SR_B1 | SR_B2 |
| Green | SR_B2 | SR_B3 |
| Red | SR_B3 | SR_B4 |
| NIR | SR_B4 | SR_B5 |
| SWIR1 | SR_B5 | SR_B6 |
| SWIR2 | SR_B7 | SR_B7 |

### 3.4 Landsat 7 SLC-off handling

After 31 May 2003, ETM+ scenes have ~22% missing data in wedge-shaped gaps. Options:
1. **Preferred:** exclude L7 post-2003 wherever L5 or L8 coverage suffices.
2. If L7 is unavoidable (2012 gap year between L5 retirement and L8 launch), the median composite over ≥4 scenes fills most gaps — but report residual gap fraction per year.

### 3.5 Compositing

Median composite over the dry-season window. Median is more robust to residual cloud than mean and cheaper than medoid.

If terrain shading is a problem in Sylhet's hills, apply a topographic correction (C-correction or SCS+C) using SRTM slope and aspect. Test whether it changes classification accuracy; report the result either way — a negative result is still a finding.

### 3.6 Feature stack

Per composite, build this band stack:

| Group | Bands | Purpose |
|---|---|---|
| Spectral | Blue, Green, Red, NIR, SWIR1, SWIR2 | Base |
| Vegetation | NDVI, EVI, SAVI | Greenness, canopy density |
| Moisture | NDWI, NDMI | Water, canopy moisture |
| Built-up | NDBI | Gazipur industrial expansion |
| Tasselled Cap | Brightness, Greenness, Wetness | Wetness is a strong forest discriminator |
| **Texture** | GLCM contrast, entropy, homogeneity on NIR | **Tea plantation vs natural forest** |
| Terrain | SRTM elevation, slope, aspect | Sylhet hills |

Total ≈ 20 bands. This is the input tensor depth for your CNN.

**On texture:** tea gardens are geometrically regular — uniform canopy height, planted rows, visible tracks. Natural hill forest is structurally chaotic. GLCM entropy over a 5×5 window separates them far better than any spectral index. This is your answer to the biggest technical threat in the thesis.

**Gate 3:** Composites generated for all epoch years, both districts. Visual QA: no cloud residue, no seam artifacts, no missing tiles. Feature stack exported for one test tile and verified in Python.

## Phase 4 — Reference and label data

**Duration:** Months 3–5 (starts in parallel with Phase 3; do not defer)

You need **two distinct datasets**. Conflating them invalidates your accuracy figures.

| | Training labels | Reference sample |
|---|---|---|
| Purpose | Teach the model | Measure the model |
| Source | Hansen GFC + BFD + your digitised polygons | Independent visual interpretation |
| Volume | Millions of pixels | 500–800 points per district |
| Quality | Noisy is acceptable | Must be high quality |
| **Overlap** | **None. Ever.** | |

### 4.1 Training labels

**Post-2000 (label-rich):**
- Hansen GFC v1.13: `treecover2000` thresholded at 30%, minus cumulative `lossyear`, plus `gain`
- BFD/BFIS forest boundaries → constrain "natural forest" class
- Tea estate boundaries (BFIS, or digitised from high-res imagery) → "plantation" class

**Pre-2000 (label-poor):** you have three honest options. Recommend option B.

| Option | Method | Cost |
|---|---|---|
| A | Start the study at 2000 | Free; loses the historical depth that motivates the thesis |
| B | **Two-regime design** — supervised DL post-2000, spectral/LandTrendr change pre-2000, explicitly framed as a methodological comparison | Moderate; strongest research narrative |
| C | Manually digitise 1990 and 1995 forest polygons for both districts | 3–4 weeks of labour; highest quality |

Option B lets you *ask a research question* about the label gap rather than apologise for it: **"How well do unsupervised change methods substitute for supervised deep learning where training labels do not exist?"** That is a publishable question.

### DECIDED 2026-07-26 — Option B, the two-regime design

**Chosen:** supervised deep learning from 2000 onward, unsupervised
spectral and LandTrendr change before 2000, framed explicitly as a
methodological comparison rather than a limitation.

**Rejected — Option A (start at 2000):** throws away the 1988–1999 depth
that Phase 2 established is available. The audit found usable imagery
back to 1988 in all three districts; discarding twelve years because
Hansen cannot label them is letting the label source dictate the study
period.

**Rejected — Option C (manually digitise 1990/1995 forest):** 3–4 weeks
of labour that competes directly with the reference sample, which is
already the binding constraint at 3,600 interpretations. Adding
digitisation work risks the accuracy assessment to improve the training
set — the wrong trade.

#### The consequence that is not obvious

**T0 = 1990 sits in the unlabelled regime.** That is fine for some
methods and impossible for others, and the difference has to be designed
around rather than discovered in Phase 7:

| Method | Works across T0 = 1990? | Why |
|---|---|---|
| Random Forest, U-Net (PCC) | **Yes** | Classify each date independently, then difference. The 1990 composite is classified by a model trained on 2000+ labels — transfer in time, not in supervision |
| NDVI differencing | **Yes** | Unsupervised, no labels needed |
| LandTrendr | **Yes** | Unsupervised temporal segmentation over the full annual series |
| **Siamese (E5)** | **No** | Direct bitemporal change detection needs change labels *for that pair*. None exist for 1990→2024 |

So E5 runs on post-2000 pairs only. Say this in the methods chapter
rather than letting a reader notice E5's date range differs from E3's.

#### What makes it a research question rather than an excuse

The two regimes **overlap from 2000 to 2024**. Run both the supervised
and unsupervised methods over that overlap, on the same reference
sample, and the difference between them is a measured quantity. That
number is the honest answer to "how far can we trust the pre-2000
figures?" — and it is reported, not assumed.

Without the overlap comparison, Option B is just two methods stapled
together. With it, the pre-2000 estimates carry a stated, empirically
grounded uncertainty. **Budget the overlap comparison explicitly in
Phase 7; it is the part that makes this decision defensible.**

### 4.2 Reference sample — the part that makes your results defensible

**Design:** stratified random sampling.

| Stratum | Gazipur | Sylhet | Bandarban |
|---|---|---|---|
| Stable non-forest | 150 | 150 | 125 |
| Stable natural forest | 150 | 150 | 125 |
| Forest loss — **permanent** | 200 | 200 | 150 |
| **Cyclical jhum disturbance** | — | — | **150** |
| Plantation | 100 | 100 | 50 |
| ~~Gain / regrowth~~ | — | — | — |
| **Total** | **600** | **600** | **600** |

**The gain/regrowth stratum was dropped on 2026-07-26** and its 50 points
moved to forest loss. Hansen's `gain` band covers **2000–2012 only** — it
was never extended annually the way `lossyear` was. Measured over our
AOIs that leaves 624 gain pixels in Gazipur and 451 in Sylhet, so 50
points would have been 8% and 11% of the entire stratum, breaking the
large-population assumption behind the variance formulae in
`src/area_estimation.py`. The stratum could not honestly have been
described as covering 1988–2024 in any case.

Regrowth is instead reported from the LandTrendr annual series, which
spans the whole study period. The freed points went to forest loss rather
than being spread evenly: loss is the change class, F1 on it is the
headline metric, and the width of its interval is the number an examiner
will press on.

**The plantation stratum is blocked** pending tea/rubber estate
boundaries from BFD/BFIS. No spectral proxy was substituted —
distinguishing plantation from natural forest spectrally is the problem
this thesis exists to solve, so using a proxy to define the stratum would
beg the question. This puts the BFD request on the critical path.

Deliberately over-sample the rare change classes. A proportional sample would give you ~15 loss points and useless confidence intervals.

**Bandarban's strata differ deliberately, and the total is held at 600.**
The cyclical-disturbance stratum is not optional — without it the
permanent-vs-cyclical split from §6.4 of the forest definition is
asserted rather than measured, and that split is the entire reason the
district was added. Its 150 points are funded by cutting the two stable
strata to 125 (Bandarban is overwhelmingly forested, so stable forest is
cheap to characterise), by halving the plantation stratum (teak and
rubber are present but far less extensive than Sylhet's tea), and by
dropping the separate gain/regrowth stratum, which in Bandarban is
subsumed by cyclical disturbance.

**Total interpretation workload: 1,800 points, each interpreted
independently by both authors = 3,600 interpretations.** At 1–2 minutes
per point that is roughly 30–60 hours *per author*. This is the binding
constraint on the whole thesis and the reason CHT was limited to one
district. Start in Month 3. If it slips, cut Bandarban — never cut the
sample.

**Interpretation protocol** *(revised 2026-07-26 — see the note below)*:
1. Generate points with `src/reference_sample.py --draw`.
2. **Author A interprets all 600 points per district.** Author B
   independently interprets a **stratified subsample of 150 per
   district** (450 total). Both use Google Earth Pro historical imagery —
   the one legitimate use of Google Earth in this thesis — plus the
   Landsat time-series chart at that point.
3. Record: class at T0, class at T3, confidence (high/medium/low), notes.
4. Compute Cohen's κ on the overlap with `src/kappa.py`. **Report this
   number in the thesis** — it is evidence of rigour and almost no
   undergraduate thesis has it.
5. Reconcile disagreements jointly; if unresolvable, flag as uncertain
   and exclude with justification. **Log what changed and why** — the
   reconciliation record is part of the audit trail, and silently
   overwriting disagreements destroys the evidence that the sample was
   independently interpreted at all.

**Why the split is uneven.** The division of labour changed on
2026-07-26: Author A now carries the analysis, Author B the written
report. The original design had both authors interpret everything, which
is no longer what will happen.

The overlap subsample exists so that κ remains computable and the thesis
statement remains **true**. A claim of independent dual interpretation
cannot be made if it did not occur (rule 8), and κ is exactly the number
an examiner asks about. 150 points per district is a few hours of work
rather than weeks, and it preserves the Gate 4 deliverable intact.

The subsample is **stratified proportionally, not drawn at random** from
the whole sample. A simple random subset would be dominated by whichever
stratum is largest, and agreement on easy classes says nothing about
agreement on the change classes the thesis rests on.

**What is honestly lost:** with one interpreter covering 450 of the 1,800
points, agreement is measured on a quarter of the sample rather than all
of it. State the overlap fraction in Chapter 6 alongside κ.

**Timing:** start this in Month 3. It takes 3–4 weeks of real work and cannot be compressed at the end.

## Phase 5 — Splitting and experimental design

**Duration:** Month 5

### 5.1 Spatially disjoint splits

**Random patch splitting is invalid here.** Neighbouring pixels are spatially autocorrelated; a random split puts near-identical patches in train and test, inflating accuracy by 5–15 percentage points. Examiners who know remote sensing will ask about this.

Correct approach:
1. Divide each district into a grid of blocks (e.g. 10 × 10 km).
2. Assign whole blocks to train / validation / test at 70 / 15 / 15.
3. Verify no patch crosses a block boundary.

Use `torchgeo`'s geospatial samplers rather than writing this yourself.

### 5.2 Cross-district transfer test

A second, stronger evaluation: **train on Gazipur, test on Sylhet, and vice versa.** This answers "does the model generalise across Bangladeshi forest types?" — far more interesting than within-district accuracy, and it's the result most likely to get you published.

### 5.3 Experiment matrix

Keep it small and complete. Six runs, not sixty.

| ID | Model | Input | Purpose |
|---|---|---|---|
| E1 | Random Forest | Per-pixel spectral + indices + texture | Baseline |
| E2 | Random Forest | + terrain | Does terrain help? |
| E3 | U-Net (ResNet-34 encoder, ImageNet pretrained) | Full stack, single date | Segmentation |
| E4 | U-Net | Full stack, no texture bands | **Ablation: does texture solve the tea problem?** |
| E5 | Siamese U-Net (FC-Siam-diff) | Bitemporal pairs | Direct change detection |
| E6 | E3 or E5, cross-district | Best model, transferred | Generalisation |

Each experiment runs with **3 random seeds**; report mean ± standard deviation. Single-run numbers are not evidence.

**Gate 5:** Splits generated and verified spatially disjoint. Experiment matrix fixed and written into the thesis methods chapter.

## Phase 6 — Model development

**Duration:** Months 5–8

### 6.1 Baseline first

Do not train a neural network until Random Forest works. The RF baseline:
- Establishes an accuracy floor
- Debugs your entire data pipeline cheaply
- Gives feature importances that tell you which bands matter (useful for the thesis discussion)

Configuration: 500 trees, `sqrt(n_features)` per split, class-balanced sampling. Train in scikit-learn on the extracted pixels, not in GEE — you need the same pipeline as the DL models for a fair comparison.

### 6.2 U-Net configuration

| Parameter | Value | Note |
|---|---|---|
| Encoder | ResNet-34, ImageNet pretrained | ResNet-50 is heavier with little gain at this data volume |
| Input channels | ~20 | Adapt first conv layer; initialise extra channels as the mean of pretrained RGB weights |
| Loss | Dice + Binary Cross-Entropy (0.5/0.5) | Handles class imbalance better than BCE alone |
| Optimiser | AdamW, lr 1e-4, weight decay 1e-4 | |
| Schedule | Cosine annealing, 100 epochs | |
| Batch size | 8–16 at 256² | Colab T4 limit |
| Augmentation | Flips, 90° rotations **only** | No colour jitter — it destroys radiometric meaning |
| Early stopping | Patience 15 on validation IoU | |

Use `segmentation-models-pytorch`. Do not implement U-Net from scratch; nobody gets credit for that, and bugs cost weeks.

### 6.3 Siamese change detection

Architecture: shared-weight encoder applied to T0 and T1 patches, features differenced or concatenated, decoder outputs a change mask. Start from FC-Siam-diff (Daudt et al., 2018) — reference implementations are public.

Pretrain the encoder on LEVIR-CD or OSCD, then fine-tune on your Bangladesh patches. Your labelled set is small; transfer learning is not optional.

### 6.4 Class imbalance

Change pixels will be 1–5% of the scene. Mitigations, in order of effectiveness:
1. Patch sampling weighted toward change-containing patches (but keep test set unweighted)
2. Dice loss
3. Focal loss (γ=2) if Dice underperforms
4. **Never** report overall accuracy as the headline metric

### 6.5 What to cut if you fall behind

In this order: Swin Transformer → ConvLSTM → XGBoost → SVM → cross-district transfer. Protect E1, E3, E4, E5 at all costs — those four are the thesis.

**Gate 6:** All six experiments complete with 3 seeds each. Results table populated with mean ± std.

## Phase 7 — Change detection and map production

**Duration:** Month 8

### 7.1 Methods to compare

| Method | Type | Implementation |
|---|---|---|
| Post-Classification Comparison (PCC) | Indirect | Classify T0 and T1, difference the maps |
| NDVI differencing + threshold | Spectral | Threshold via Otsu or 2σ from the stable-forest distribution |
| Siamese network | Direct | E5 output |
| LandTrendr | Temporal segmentation | GEE `ee.Algorithms.TemporalSegmentation.LandTrendr` on annual NBR |

PCC accumulates error from both dates (if each map is 90% accurate, the change map is ~81%). Say this in the discussion — it's the standard argument for direct methods, and your Siamese result either supports it or doesn't.

### 7.2 Post-processing

1. **Minimum mapping unit filter:** remove connected components smaller than 0.5 ha (≈6 pixels). This directly implements your forest definition.
2. **Plantation mask:** exclude class 2 pixels from "forest loss" totals; report plantation change as a separate, clearly labelled statistic.
3. **Temporal consistency check:** a pixel cannot go forest → loss → forest → loss repeatedly. Flag and inspect implausible trajectories.

### 7.3 Outputs

- Forest/non-forest map per epoch, per district (GeoTIFF, EPSG:32646)
- Change map T0→T3 (GeoTIFF, categorical)
- Loss-year map from LandTrendr (GeoTIFF)
- Hotspot density map (kernel density of loss pixels)

**Gate 7:** Maps produced for all methods and both districts. Visual inspection against Google Earth Pro historical imagery at 10 random loss patches — do they look real?

## Phase 8 — Accuracy assessment and area estimation

**Duration:** Month 9

**This is the phase that separates a thesis from a class project. Budget properly for it.**

### 8.1 Metrics

| Metric | Report? | Note |
|---|---|---|
| Overall Accuracy | Yes, with CI | Inflated by the dominant class — never the headline |
| Producer's Accuracy (recall) per class | Yes | Omission error |
| User's Accuracy (precision) per class | Yes | Commission error |
| F1 per class | Yes | **Headline metric for the change class** |
| IoU per class | Yes | Standard in segmentation literature |
| Cohen's κ | **Optional, with a caveat** | Pontius & Millones (2011) argue it is uninformative for map accuracy; if your supervisor requires it, include it but cite the critique |

Report every metric with a 95% confidence interval derived from the reference sample.

### 8.2 Area estimation — Olofsson et al. (2014)

Do not report area by counting classified pixels. Pixel counting is biased by classification error; the standard is a stratified estimator that corrects using the confusion matrix.

Procedure:
1. Build the error matrix from your reference sample, expressed as **proportions of area** (weight each cell by the mapped area proportion of its stratum).
2. Compute the adjusted area estimate for each class.
3. Compute the standard error and 95% confidence interval.
4. Report as: *"Forest loss in Gazipur, 1990–2024: 18,400 ha ± 2,100 ha (95% CI)"*.

Implement this in `src/area_estimation.py` — it is roughly 60 lines of numpy. Cite Olofsson et al. (2014), *Remote Sensing of Environment* 148:42–57.

**Reporting a number without a confidence interval is the most common reason remote sensing papers get rejected.** Doing it correctly at undergraduate level is genuinely distinguishing.

### 8.3 Cross-validation against independent sources

| Source | Comparison |
|---|---|
| Hansen GFC loss 2000–2024 | Do your totals agree within CI? |
| BFD / national REDD+ figures (2000–2015) | Institutional cross-check |
| FAO FRA Bangladesh country report | National-scale sanity check |

Disagreement is not failure — explain it. "Our estimate exceeds Hansen's because Hansen's tree-cover definition includes tea plantation" is a *result*, not an error.

**Gate 8:** Error matrices complete, adjusted areas with CIs computed for both districts, cross-validation table populated.

## Phase 9 — Analysis and interpretation

**Duration:** Month 9–10

### 9.1 Answer each research question explicitly

Structure the results chapter as one section per RQ, with the answering table or figure immediately after the question restated.

| RQ | Deliverable that answers it |
|---|---|
| How much forest was lost? | Adjusted area table with CIs, per district, per epoch |
| Which DL model performs best? | Experiment matrix results, mean ± std, 3 seeds |
| DL vs traditional ML? | E1/E2 vs E3/E5 comparison, plus inference-time column |
| Which change detection method is most accurate? | Per-method error matrices on the same reference sample |

### 9.2 Driver analysis

Correlate loss location with:
- Distance to roads (OSM)
- Distance to built-up areas (GHSL)
- Slope (SRTM) — expect a strong negative relationship in Sylhet
- Distance to tea estate boundaries — expect a strong positive relationship in Sylhet

A simple logistic regression of loss-probability on these covariates gives you a defensible driver section without overreaching.

### 9.3 The comparison that makes the thesis interesting

Gazipur and Sylhet fail differently, and that contrast is your intellectual contribution:

| | Gazipur | Sylhet |
|---|---|---|
| Loss signature | Abrupt, geometric, permanent conversion | Gradual, fragmented, partial degradation |
| Detection difficulty | Easy — high spectral contrast | Hard — plantation confusion, terrain shadow |
| Expected model ranking | RF may be competitive with U-Net | U-Net and texture features should dominate |
| Policy implication | Zoning and industrial siting | Plantation boundary enforcement |

If your results show that model choice matters far more in Sylhet than Gazipur, **that is your headline finding** — it means the value of deep learning is conditional on landscape complexity, which is a genuinely useful thing to have demonstrated.
